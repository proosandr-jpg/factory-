## Правила работы
1. Каждый агент работает в своём Git Worktree, свою ветку.
2. Перед началом работы читать `COORDINATION.md` и `docs/agent-protocol.md`.
3. Брать задачу со статусом `ожидает` или `заблокировано` (если зависимости готовы), ставить `в работе`.
4. После завершения — коммит в свою ветку, пуш, обновить `COORDINATION.md` (статус → `на проверке`).
5. `agent-git` делает ревью, мержит в `main`, статус → `завершено`.
6. Никогда не коммитить напрямую в `main` (кроме `agent-git` после ревью).
7. `.env` с реальными ключами НЕ коммитится (в .gitignore).

- scipy 1.18.1 (требует numpy>=2.0 — конфликт с numpy 1.26.4)

**Диск**: КРИТИЧНО — /dev/sda1 50G, использовано 49G, свободно 0 байт (100%)

**Модели TTS**: Файлы *.safetensors, *.pt, *.onnx не найдены в системе (кроме скачанных в /root/f5tts-cpu/ckpts/, которые тоже могут быть удалены из-за нехватки места)

**Системный TTS**: espeak-ng, festival, flite не установлены. Только libflite1 (библиотека без утилит командной строки)

**Системный Python**: python3.12, без pip-пакетов для TTS

### Проблемы

1. **Диск заполнен на 100%** — нет места для установки новых пакетов, моделей или Docker-образов
2. **Конфликт numpy**: f5-tts требует numpy<=1.26.4, но scipy 1.18.1 требует numpy>=2.0, transformers 5.23.0 требует scipy>=1.4. Это неразрешимый конфликт в одном venv
3. **torch 2.15.0+cpu вместо 2.1.2** — f5-tts явно требует torch==2.1.2, но установлен 2.15.0+cpu
4. **Только Python 3.12** — f5-tts рассчитан на Python 3.10

### Возможные пути

**Вариант А: Исправить текущий venv**
- Откатить torch до 2.1.2, torchaudio до 2.1.2, transformers до версии совместимой с numpy 1.26.4, downgrade scipy
- Плюсы: быстрее, чем пересоздавать venv
- Минусы: очень хрупко, много взаимных конфликтов, требует много времени на подбор версий, диск заполнен на 100% — может не хватить места
- Риск: высокий
- Время: 30–60 мин

**Вариант Б: Пересоздать venv на Python 3.10**
- Нет Python 3.10 в системе — нужно установить из исходников или deadsnakes PPA
- Плюсы: чистое окружение под f5-tts спецификацию
- Минусы: нет Python 3.10, установка сложна, диск 100% заполнен
- Риск: очень высокий
- Время: 2–4 часа

**Вариант В: Docker-образ F5-TTS**
- Docker доступен
- Плюсы: изоляция, не трогаем системный Python, правильные версии пакетов внутри контейнера
- Минусы: образ может быть большим (2–4 ГБ), диск 100% заполнен — нужно освободить место, нужно настроить volume для доступа к файлам референса и вывода
- Риск: средний (диск)
- Время: 30–60 мин (после освобождения места)

**Вариант Г: Альтернативная TTS с клонированием на CPU**
- XTTS-v2 (Coqui) — лицензия ограничительна, нужна регистрация
- Piper TTS — не клонирует голос
- Tortoise TTS — медленный на CPU, сложные зависимости
- Риск: высокий (лицензии, качество, время)
- Время: 1–3 часа

### Рекомендация

**Вариант В (Docker)** — самый реалистичный. Не ломаем текущее окружение, не устанавливаем конфликтующие пакеты.

**Необходимо сделать перед стартом:**
1. Освободить место на диске (удалить неиспользуемые пакеты, кэш pip, логи, возможно старые модели)
2. Скачать Docker-образ F5-TTS
3. Запустить контейнер с volume mapping для /root/f5tts-cpu/ckpts/ и /root/factory/output/audio/
4. Получить транскрипцию референса от локального агента
